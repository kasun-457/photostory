## 3. 보정 지도의 내용 (모델 출력)

잘라 낸 얼굴 크기(학습 해상도 512 또는 768) 기준. 앱에서는 원본 해상도로 키워 쓴다.

| 지도 | 채널 | 뜻 | 강도 부위 |
|---|---|---|---|
| 유동화 | 2 (dx, dy) | 화소가 어디로 움직이는지. 부드러운 흐름 | 눈·눈썹·코·입·얼굴형·목·어깨·머리카락 (영역마다 나눠 곱함) |
| 피부 | 1 (0~1) | 스냅숏 1(수정-01)을 섞는 비율 = 작업 내역 브러시 | 피부 |
| 톤 배율 | 3 (RGB, log) | 화소마다 곱할 색 배율 (저주파). 닷징·버닝, 머리카락 밝기·색까지 한 지도로 | 명암 (머리카락 영역은 머리카락) |
| 메움 | 1 (0~1) | 부분 생성형이 새로 그릴 곳 | 피부·명암·머리카락 (무엇을 지웠는지에 따라) |

- 강도 0%는 지도 0, 100%는 모델 그대로, 200%는 두 배. **대칭 계열은 지금처럼 다시 재서 완전 대칭을 넘지 않게 자른다** (설계서 2-3).
- 확신도: 모델이 지도마다 확신도를 함께 내고, 낮으면 덜 고친다 (가이드 §0).

- 처음엔 밝게·어둡게 두 지도로 나누려 했으나, 실제 수정본에서 머리카락 색·밝기를 크게 바꾼 경우가 보여서(2026-11-27 표본) RGB 배율 하나로 바꿈. 강도는 배율의 지수로 곱한다 (배율^강도).

### 3-1. 정답 지도 뽑는 방법 (`training/extract_targets.py`)

1. 잘라 낸 수정본·원본을 1/2로 줄여 RAFT로 '수정본 화소가 원본의 어디서 왔나'를 구하고, 부드럽게 다듬은 뒤 사람 영역 밖은 0으로.
2. 원본을 그 흐름으로 옮김(o_w). 사람 영역 안에서만 흐린 수정본 ÷ 흐린 o_w = 톤 배율.
3. t = o_w × 배율. 창 안 최소제곱으로 (수정본 − t) ≈ α(S1(t) − t)의 α를 품.
4. 그래도 남은 오차가 8 넘는 덩어리 = 메움.
5. 단계마다 평균 오차를 적어서 (원본 그대로 → 흐름 → 톤 → 피부) 얼마나 설명됐는지 본다.
6. 흐름에서 **몸 전체 닮음 변환(배치)을 RANSAC으로 먼저 뺀다.** 표본 20쌍 중 3쌍이 사진 전체를 2~2.7° 돌린 것이었음
   (다시 수평 잡기 또는 몸 회전). 이건 `affine`으로 적어만 두고 유동화 지도에는 넣지 않는다.
7. 피부 비율은 피부 영역(얼굴·몸 피부, 수정본 위치로 옮긴 것) 안에서만.

표본 20쌍 결과 (0~255 평균 오차, 사람 영역): 원본 그대로 4~28 → 흐름 후 4~17 → 톤 후 1.5~11 → 피부 후 1.5~11.
배치 뺀 유동화는 평균 0.4~8px, 최대 8~71px (조각 px, 얼굴 폭 384 기준).

확실하지 않은 것 (표본을 보고):
- 안경테 둘레에 피부 비율이 고리처럼 잡힘 → 안경 영역을 빼야 할 수 있음
- 메움이 머리카락 윤곽을 따라 길게 잡힘. 일부는 잔머리 정리지만 일부는 배경을 흰색으로 올리면서 머리카락 끝이 밝아진 것 (배경은 규칙 단계) → 학습 때 윤곽 띠는 따로 다룰지 결정
- 톤 배율에 사진 전체를 밝게 한 것이 섞여 있음 → 전체 보정(한 장에 하나)과 부분 톤을 나눌지 결정

### 3-2. 보정 지도 모델 (`training/model.py`, `training/train_map.py`)

- 입력 (조각의 1/2 = 704×864): 원본 + **좌우 뒤집은 원본** + 얼굴 부위 6 (윤곽·눈·눈썹·입술·코·턱선) + 영역 5 (사람·머리카락·얼굴 피부·몸 피부·옷) + 유효 + 좌표 2.
  조각은 두 눈 가운데가 세로 중심이라, 뒤집은 원본을 같이 넣으면 화소마다 반대쪽 얼굴을 바로 본다 (대칭 보정용).
- 구조: U-Net (폭 16·48·96·192·256) + 가운데(1/16)에 주의 층 2개. 790만 개 값, 처음부터 학습 (남의 가중치 없음).
  RTX 3060에서 묶음 4개 0.87초/걸음, 메모리 4.9GB (중간값 다시 계산하기 사용).
  처음 모양(폭 32부터)은 17.6GB가 필요해서 12GB를 넘었음.
- 출력: 유동화 2 · 피부 비율 1 · 톤 배율 3 · 메움 1. 처음엔 '아무것도 고치지 않음'에서 시작하게 맞춤.
- 지도 적용 식 `apply_maps`는 학습 손실과 앱이 같이 쓴다:
  수정본 x = 원본(A·x + 강도·flow) × exp(강도·gain), 그 위에 + (강도·alpha)·(S1 − t). 배치 A에는 강도를 곱하지 않는다.
  정답 지도로 이 식을 돌리면 결과 오차가 3.6~18 → 1.4~3.8 (정답 뽑기와 같은 수준) → 식이 맞음.
- 손실: 지도마다 정답과의 차 (사람 영역 안) + **결과 손실** (예측 지도를 적용한 것 vs 수정본, 메움 자리 뺌).
  정답 지도가 정확하지 않은 곳도 결과로 배우게 하려는 것.
- 검증 숫자: 결과 오차(0~255) — 원본 그대로 / 정답 지도 적용 / 예측 지도 적용. 예측이 '원본 그대로'보다 얼마나 '정답 지도'에 가까워지는지 본다.
- 좌우 뒤집기 늘리기: 유동화 x 부호와 배치 변환도 같이 뒤집음 (테스트로 확인).

## 4. 학습 환경

- 개발 PC: RTX 3060 12GB, Python 3.12. PyTorch(CUDA)와 학습용 패키지는 `training/requirements.txt`로 따로 깐다 (판매 프로그램과 분리).
- 광학 흐름(3-3)은 torchvision RAFT (BSD) — 정답 뽑기에만 쓰고 판매 프로그램에는 들어가지 않음.
- 예상 시간 (추정): 3-2 자르기 1쌍 ~1.5초 → 13,000쌍 약 5~6시간. 3-3 약 3~4시간. 3-4·3-5 학습은 각각 하루 안팎.
- 작업 폴더 용량 (실제): 조각 34GB + 정답 지도 14GB (자르기 63%·지도 40% 시점) → 다 끝나면 약 55GB + 80GB 안팎. 넉넉히 150GB를 비워 둔다.

### 4-1. 다른 컴퓨터에서 이어 하기

git에는 **코드와 문서만** 올라간다. 원본 사진과 작업 폴더(조각·정답 지도·`index.csv`·`crops.csv`·`targets.csv`)에는 손님 사진과 이름이 들어 있으므로 절대 올리지 않는다 (설계서 8-3).

1. 코드 받기: `git pull`
2. 패키지: `py -3.12 -m pip install --user -r requirements-dev.txt`, `py -3.12 -m pip install --user -r training/requirements.txt --index-url https://download.pytorch.org/whl/cu126` (그래픽카드에 맞게), `py -3.12 tools/fetch_models.py`
3. 경로 정하기 (그 컴퓨터의 경로로. 한 번만):
   ```powershell
   setx PHOTOSTORY_SRC "E:\1_촬영\3_증명사진"
   setx PHOTOSTORY_WORK "C:\photostory_data"
   ```
   새 PowerShell 창부터 적용된다. 안 정하면 `D:\1_촬영\3_증명사진`·`C:\photostory_data`.
   보호: D: 전체 + 원본 폴더 + 원본이 작업 폴더와 다른 드라이브에 있으면 그 드라이브 전체 (`training/safety.py`). 작업 폴더를 그 안에 두면 도구가 멈춘다.
4. 작업 폴더를 가져갈지 정하기:
   - **가져가면 (외장 디스크로 통째 복사)**: 이어서 바로 계속한다. 짝 이름(key)은 원본 폴더 안의 상대 경로로 정해지므로, 원본 폴더 안의 년/월/사람 폴더 구조가 같으면 경로가 달라도 그대로 맞는다.
   - **안 가져가면**: 처음부터 다시 만든다 (3-1 몇 분, 3-2 약 5시간, 3-3 약 10시간).
5. 이어서 돌리기 (모두 끊긴 곳부터 이어 한다. 중간에 끊겨 반쯤 적힌 마지막 기록 줄은 다음 시작 때 잘라 내고 그 짝은 다시 한다):
   ```powershell
   py -3.12 -m training.index_pairs        # 작업 폴더를 안 가져온 경우만
   py -3.12 -m training.crop_pairs --workers 4
   py -3.12 -m training.extract_targets
   py -3.12 -m training.train_map --name v1 --steps 40000
   ```
   자르기와 지도 뽑기는 함께 돌려도 된다 (지도 뽑기는 그때까지 잘린 짝만 하므로, 자르기가 끝난 뒤 한 번 더 돌린다).

## 5. 확실하지 않은 것

- 광학 흐름이 피부를 문지른 곳(결이 바뀐 곳)을 움직임으로 착각할 수 있음 → 흐름은 저주파로 제한하고, 3-3 결과를 표본으로 눈으로 확인한다.
- 2020~2021년 수정본은 지금 방식과 다를 수 있음 → 연도별 평가를 따로 보고 필요하면 오래된 것을 덜 쓴다.
- 배경(흰색 255)·안경 얹기는 수정본에도 들어 있지만 규칙으로 이미 정확하므로 학습 대상에서 뺀다 (사람 영역 밖·안경 손님은 손실에서 제외).
