# 사진이야기 증명사진 자동 보정 프로그램 설계서 (v1.0)

- 작성일: 2026-11-26 (v0.2: 사용자 답변 8개 반영 / v1.0: 기술 스택·개발 순서 확정)
- 근거 문서
  - 보정 가이드: `Id photo retouch-v22.zip` 안의 `SKILL.md` (이하 **가이드 §번호**)
  - 이전 프로그램 분석: `photostory_ver1.52_기능분석.md` (이하 **v1.52**)
- 이 문서의 원칙
  1. 프로그램 흐름은 원클릭 방식이다: 손님 정보 입력 → 사진 업로드 → 자동 처리 → 결과 확인 → 출력.
  2. 보정 **결과 기준**은 가이드를 따른다. 가이드와 v1.52가 다르면 가이드가 우선이다.
  3. **코드는 처음부터 새로 작성한다.** v1.52의 코드는 가져오지 않고, 기능과 동작 방식만 참고한다.
  4. 사용자 결정이 가이드보다 우선이다. 원본 덮어쓰기, 중간 저장, 처리 중 질문, 본인 유사도 검사는 하지 않는다.
  5. 손님은 **한 명씩** 처리한다.

```

        │  [다음]
        ▼
[② 사진 업로드]
  안경 아니오 → 칸 1개: 원본
  안경 예     → 칸 2개: 원본(안경 벗은 사진) + 안경 쓴 사진
  필요한 칸이 모두 채워져야 [시작] 버튼이 켜짐

  [전문가 모드] 부위별 강도 슬라이더, 증명사진 얼굴 크기·위치 미세 조정 → 바로 다시 계산

        ▼
[⑤ 출력]

  {이름}_수정본.jpg
  {이름}_전송.jpg  (규격이 여러 개면 {이름}_전송_{규격}.jpg)
  {이름}_a4출력.jpg
```

### 1-1. 손님 정보 항목

| 항목 | 값 | 쓰이는 곳 |
|---|---|---|
| 이름 | 글자 | 파일 이름, A4 라벨 |
| 용도 | 규격 목록에서 1개 이상 | 트리밍, 배경색, A4 줄 수 |
| 성별 | 남 / 여 | 측정 템플릿 (가이드 §5-1 여자: 머리카락 폭, §5-2 남자: 귀·두상) |
| 안경 착용 | 예 / 아니오 | 사진 칸 수, 안경 옮기기 단계 |
| 보정 강도 | 기본 모드: 약하게 / 기본 / 강하게. 전문가 모드: 부위별 슬라이더 (2절) | 보정 단계의 세기 |

### 1-2. 사진 업로드

- 형식: jpg, png, bmp, webp, tif + RAW(cr2, cr3, nef, arw, dng 등). 한글 경로 지원.
- 끌어다 놓기와 [열기] 둘 다 지원한다.
- 안경 칸이 있을 때 두 장을 한꺼번에 끌어다 놓으면, 이름이 `안경`으로 끝나는 파일(예: `홍길동_안경.jpg`)을 안경 칸에 넣는다. 구분할 수 없으면 놓은 순서대로 넣고, 칸을 서로 바꾸는 버튼을 둔다.
- 칸마다 미리보기를 작게 보여 준다. 얼굴을 찾지 못한 사진은 그 자리에서 알려 준다.

## 2. 보정 강도

### 2-1. 기준

- **100% = 학습한 모델이 정한 보정량**, 곧 성현님이 평소 하던 수준이다.
- 무엇을 얼마나 고칠지(주름·모공, 번들거림, 다크서클 등 세부 항목)는 **학습한 모델이 사진마다 정한다.** 강도는 그 결과에 곱하는 배율이다.
- 0%는 그 부위를 고치지 않는다는 뜻이다.

### 2-2. 기본 모드

- 버튼 3개: **약하게 / 기본 / 강하게**. 모든 부위에 같은 값이 들어간다.
- 처음 값: 약하게 = 60%, 기본 = 100%, 강하게 = 140%. 샘플로 결과를 보고 조정한다.

### 2-3. 전문가 모드

- 부위마다 슬라이더 하나 (0~200%, 1% 단위). 슬라이더 위에 약하게·기본·강하게 위치가 눈금으로 표시된다.
- 슬라이더 조작 (v1.52 방식): 더블클릭 = 기본값, 방향키 = 1%, Shift+방향키 = 5%, 숫자 직접 입력.
- 손님 정보 화면과 결과 화면 양쪽에서 같은 슬라이더를 쓴다. 결과 화면에서 바꾸면 바로 다시 계산한다. 무거운 분석은 다시 하지 않으므로 빠르게 반영된다 (6-1).
- [모두 약하게] [모두 기본] [모두 강하게] 버튼으로 한꺼번에 맞출 수 있다.

| 부위 | 포함되는 보정 |
|---|---|
| 피부 | 잡티, 피부 결, 피부톤 |
| 명암 | 닷징·버닝, 콧볼 옆 그림자 |
| 눈 | 눈 크기·높이, 눈동자 위치, 쌍꺼풀, 반사점 |
| 눈썹 | 눈썹 위치·톤 |
| 코 | 코 중심·콧볼 |
| 입 | 입 중심·입꼬리 수평 |
| 얼굴형·턱 | 턱 좌우, 턱선, 볼라인 |
| 목·어깨 | 목 대칭, 몸 회전, 어깨 수평·주름 |
| 머리카락 | 잔머리, 장식 제거, 머리카락 밝기 |

- **대칭 계열(눈·코·입·얼굴형·목)은 완전 대칭을 넘지 않는다.** 강하게로 올려도 좁은 쪽(눈은 큰 쪽)에 정확히 맞는 지점에서 멈춘다.
- **강도와 상관없는 것:** 수평, 규격 배치(정수리·턱·중심), 배경색. 이 값들은 규격으로 정해져 있다.

### 2-4. 증명사진 배치 미세 조정 (전문가 모드, 결과 화면)

- 얼굴 크기 ±10%, 위아래 위치 ±5% (v1.52 7-2).
- 규격 기준선을 벗어나면 규격 맞춤 표시가 주황으로 바뀐다. 출력은 막지 않는다.
- 규격이 여러 개면 규격마다 따로 조정한다.

## 3. 자동 처리 파이프라인

무거운 분석(**prepare**, 사진마다 1회)과 보정 적용(**render**)을 나눈다. 강도 슬라이더를 움직이면 render만 다시 한다.

### 3-1. prepare (사진마다 1회)

| # | 단계 | 내용 |
|---|---|---|
| P1 | 읽기 | 한글 경로, RAW 현상, 색 프로파일을 sRGB로 |
| P2 | 인식 | 얼굴 점 + 어깨 관절 + 사람 영역 (저해상도) |
| P3 | 정밀 측정 | P2 위치 주변을 원본 해상도로 다시 보고 실제 경계를 찾음: 눈 바깥 꼭짓점, 홍채, 눈썹 아래 끝, 턱 끝, 턱·목 꺾임점, 정수리, 귀 끝, 목 좌우 경계, 어깨 (가이드 §4·§5) |
| P4 | 보정 지도 | 학습한 모델이 부위별 보정 지도(어디를 얼마나)를 만듦. 강도는 여기에 곱함 |
| P5 | 안경 짝 정렬 | 안경 쓴 사진을 원본 좌표에 맞추고 안경테만 떼어 둠 (안경 착용일 때) |

공통 규칙
- **보수적 기본값 (가이드 §0):** 각 단계는 판단 확신도를 함께 낸다. 확신이 낮으면 덜 고치거나 건너뛴다. 처리 중에 사용자에게 묻지 않는다.
- **측정 → 적용 → 다시 측정:** 대칭·목·어깨 단계는 적용 뒤 다시 재서 목표에 못 미치거나 넘치면 조정한다.
- **단계 켜고 끄기:** 전문가 모드의 설정에서 단계마다 켜고 끌 수 있다. 꺼진 단계는 출력에서도 빠진다.
- **학습 모델이 준비되기 전:** 3·4·7번은 가이드의 Photoshop 액션 값(수정-01: 중간값 25px → 흐림 8px → 노이즈 6% → 80%, 닷징버닝: 곱하기·스크린)을 그대로 재현하는 규칙 방식으로 동작한다. 학습 모델이 준비되면 모델만 바꾼다 (6-2).

### 3-3. 결과 검사 (가이드 §17 중 자동으로 검사할 수 있는 것)

| 검사 | 기준 |
|---|---|
| 비대칭 | 턱선·볼라인·코·입 값이 원본보다 0에 가까움 |
| 목 | 좌우 차 20px 미만, 목 폭이 원본보다 좁아지지 않음 |
| 배경 | 흰색 255 / 말레이시아 #1399f8 / 인도네시아 #f1191a |
| 전송본 | 규격 크기·dpi, 정수리·턱·중심이 기준선에 맞음 |
| A4 | 300dpi, 장수·간격·라벨이 규칙대로 |

본인 유사도 검사는 하지 않는다. 검사 결과와 "건너뛴 단계, 남겨 둔 점"은 결과 화면에 짧게 보여 주고 파일로는 저장하지 않는다.

## 4. 출력 규칙 (가이드 우선)

| 항목 | 규칙 |
|---|---|
| 파일 이름 | `{이름}_수정본.jpg`, `{이름}_전송.jpg` / `{이름}_전송_{규격}.jpg`, `{이름}_a4출력.jpg` |
| 같은 이름 파일 | [덮어쓰기] [번호 붙이기 → `{이름}_수정본(2).jpg`] [취소] 중 선택. 세 파일에 같은 선택을 적용한다 |
| 출력 폴더 | [출력]을 누를 때 선택. "이 위치 계속 사용"을 켜면 다음부터 묻지 않음 |
| JPEG | Photoshop 품질 12에 해당하는 설정 (샘플과 비교해서 맞춤) + DPI 정보 + sRGB ICC |
| 전송 dpi | 기본 300. 규격에서 다른 dpi를 지정할 수 있음 (예: 640) |
| A4 | 2480×3508px, 300dpi, 흰색. 첫 사진 x=146, 간격 30px, 윗변 y=22, 여러 규격이면 줄마다 +35px. 전송 dpi가 300이 아니면 실제 크기(mm)를 유지한 채 300dpi로 바꿔서 붙임 |
| 사진 테두리 | 1px 바깥쪽 획, RGB(180,180,180) |
| 라벨 | `{이름} ({규격})`, 14pt(58px), RGB(180,180,180), 시계 방향 90°. 글꼴은 무료 오픈 글꼴 중 설정에서 선택 |
| 마무리 | A4 전체에 밝기 +5 (Photoshop 계산식과 맞춤) |
| 인쇄 | 하지 않음. 파일만 저장 |

### 4-1. 규격 데이터

- 규격 하나 = `specs/` 안의 파일 하나. 가이드 §15-1의 14종으로 시작한다.
- 항목: 이름, 크기(cm), 전송 dpi(기본 300), 정수리~턱(cm), 머리 윗공간(cm), 턱 최대선 여유(기본 0.1cm), 배경색, A4 장수, 별칭(예: "면허증" → 여권/운전면허).
- 여권·운전면허는 가이드의 실제 템플릿 값(정수리 15.4px, 턱 405.6~417.4px)을 그대로 쓴다.
- **사진관이 설정 화면에서 규격을 추가·수정·삭제할 수 있다.** 기본 14종은 삭제 대신 숨기기만 하고 [기본값으로 되돌리기]를 둔다. 입력값이 맞지 않으면(예: 머리 윗공간 + 정수리~턱이 사진 높이보다 큼) 저장 전에 알려 준다. A4 장수를 비우면 가이드 §16 공식으로 계산한다.

## 6. 프로그램 구조

```
사진이야기/
  app/            화면 (PySide6). 계산하지 않고 표시만 함
    customer_view   ① 손님 정보
    upload_view     ② 사진 업로드
    result_view     ④ 결과
    settings_view   설정
    widgets/        강도 슬라이더, 비교 화면 등
  core/
    pipeline.py   prepare / render, 단계 실행·취소·캐시
    session.py    손님 한 명의 작업 상태 (다음 손님이면 통째로 지움)
    measure/      정밀 측정 (가이드 §4·§5)
    io/           읽기(RAW·한글 경로)·쓰기(JPEG·ICC·DPI)
  steps/          보정 단계 하나 = 파일 하나 (3-2 표의 1~17)
  models/
    roles.py      역할별 표준 틀: 얼굴점, 자세, 사람 영역, 매팅, 채우기, 보정 지도
    adapters/     모델마다 어댑터 하나
    models.yaml   역할 → 어댑터·파일·라이선스(상업 가능/불가)·버전
  specs/          규격 파일
  layouts/        A4 배치 규칙
  training/       학습 도구 (개발 PC 전용, 판매 프로그램에는 들어가지 않음)
  tests/          단계별 테스트 + 기준 샘플 비교
  docs/
```

### 6-1. 성능

| 방법 | 내용 |
|---|---|
| 분석은 1회 | prepare 결과를 모든 단계가 함께 씀. 강도를 바꾸면 render만 다시 |
| 미리보기 먼저 | 긴 변 1,400px로 먼저 계산해 보여 주고, 원본 해상도는 뒤에서 이어서 |
| 슬라이더는 미리보기로 | 슬라이더를 움직이는 동안은 미리보기만 다시 계산하고, 손을 떼면 원본 해상도를 계산 |
| 필요한 영역만 원본 해상도 | 무거운 처리는 얼굴·머리·목 영역에만 |
| 늦게 끝난 결과 버리기 | 설정이 바뀌거나 다음 손님으로 넘어가면 진행 중인 계산을 취소하고 결과를 무시 |
| 모델 미리 읽기 | 프로그램을 켤 때 뒤에서 모델을 읽어 두고 끝까지 사용 |
| 업로드하면서 분석 시작 | 사진이 칸에 들어가는 순간 P1~P3를 시작해서 [시작]을 누를 때는 이미 진행 중 |
| 단계별 시간 기록 | 어느 단계가 느린지 기록 |

예상 처리 시간은 RTX 3070 기준 한 사람당 약 3~6초다 (계산한 추정치이며, 첫 사진은 모델을 읽는 시간이 더 걸린다).

### 6-2. 모델 교체 구조

- 보정 단계는 모델 이름을 모르고 **역할**(얼굴점, 사람 영역, 보정 지도 등)만 요청한다.
- 얼굴 점은 모델 번호가 아니라 **우리 표준 이름**(`턱끝`, `왼눈_바깥꼭짓점`)으로 바꿔서 넘긴다. 어댑터가 번호를 이름으로 바꾼다.
- 지금은 비상업 오픈 모델도 쓸 수 있다. 판매용 빌드는 `models.yaml`에 상업 불가 모델이 있으면 멈춘다.
- 모델을 바꾸면 기준 샘플 사진의 측정값 차이를 자동으로 보고한다.
- 학습 모델(보정 지도)도 같은 방식이다. 처음에는 가이드 규칙 어댑터로 시작하고, 학습이 끝나면 학습 모델 어댑터로 바꾼다.

## 7. v1.52와의 관계

- **코드는 쓰지 않는다.** 최적화를 위해 처음부터 새로 작성한다.
- 기능과 동작 방식은 참고한다. 참고하는 기능은 3-2 표의 "참고 기능" 열과 2-3의 슬라이더 조작 방식이다.
- 가져오지 않는 것: 붓 도구 전체, 조각 편집·윤곽선 끌기 화면, 레벨·곡선·범위 보정 화면, 펜 압력, 손떨림 보정, 되돌리기 기록, 배경 팔레트, PDF 인쇄, `_edited`·`_sheet` 파일 이름, mm 기준 A4 배치.

## 8. 위험 요소

1. **GPL 코드:** 새로 작성하므로 v1.52 코드 문제는 없다. 다만 GPL 프로그램(darktable·GIMP·Krita·RawTherapee)의 코드를 보고 옮기는 방식은 쓰지 않는다. 알고리즘은 논문이나 공개 설명을 바탕으로 구현한다.
2. **학습 전 품질:** 학습 모델이 준비되기 전에는 규칙 방식이라 성현님 결과와 차이가 날 수 있다.
3. **고객 사진:** 학습·테스트에 쓰는 사진은 git에 올리지 않는다.
4. **Photoshop과 결과 맞추기:** 품질 12 JPEG와 밝기 +5는 실제 Photoshop 결과와 비교해서 맞춰야 한다.

## 9. 기술 스택과 개발 순서 (2026-11-26 확정)

1. 기술 스택: Python + PySide6 + OpenCV/NumPy + ONNX Runtime, Nuitka 빌드.
2. 개발 순서:
   - 0단계: 화면 흐름 ①~⑤, 파이프라인 엔진, 규격 데이터, 수평·전송 트리밍·흰 배경·A4 출력 (보정 없이도 출력 3종이 나오는 상태)
   - 1단계: 정밀 측정, 피부·명암 (규칙 방식), 보정 강도, 전문가 모드
   - 2단계: 대칭·목·어깨, 안경 옮기기, 머리카락
   - 3단계: 학습 데이터 추출과 모델 학습, 학습 모델로 교체
   - 4단계: 판매 준비 (설치 프로그램, 라이선스, 자동 업데이트, 상업용 모델 교체)
